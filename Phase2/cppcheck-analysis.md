# Running Cppcheck

## Objective

Run Cppcheck on the BIRD v2.17.1 source code to identify potential bugs, coding issues, style problems, performance improvements, portability concerns, and other static analysis findings.

---

## Output Directory

A dedicated directory was created to store the generated report.

```bash
mkdir -p reports/cppcheck
```

---

# Running Cppcheck

Command:

```bash
cppcheck \
  --enable=all \
  --inconclusive \
  --force \
  --xml \
  --xml-version=2 \
  . 2> reports/cppcheck/cppcheck-result.xml
```

## Command Options

| Option | Description |
|---------|-------------|
| `--enable=all` | Enables all available checks, including warnings, style, performance, portability, information, and unused code analysis. |
| `--inconclusive` | Reports potential issues with lower confidence that may require manual verification. |
| `--force` | Forces analysis of all configurations and source files. |
| `--xml` | Generates the output in XML format. |
| `--xml-version=2` | Produces XML using version 2 of the Cppcheck output schema. |

---

# Result

The analysis completed successfully.

Generated report:

```
reports/cppcheck/cppcheck-result.xml
```

The XML report contains all findings generated by Cppcheck and will be used later for:

- Manual review of reported issues.
- Importing external issues into SonarQube.

## Using Compilation Context

### Objective

To reduce analysis noise and false positives, Cppcheck was re-executed using the project's compilation database. Instead of analyzing the source code without build information, Cppcheck was provided with the actual compiler commands, include paths, and compiler options generated during the BIRD build process.

The compilation database (`compile_commands.json`) was generated using **Bear** while rebuilding the project.

---

## Generating the Compilation Database

```bash
bear -- make -j1
```

This command generated the following file:

```text
compile_commands.json
```

The compilation database contains the actual compilation commands used by GCC, including:

- Source files
- Include directories
- Compiler flags
- Preprocessor definitions

Providing this information allows Cppcheck to analyze the project using the same compilation context as the real build.

---

## Running Cppcheck with Compilation Context

### Command

```bash
cppcheck \
  --project=compile_commands.json \
  --enable=all \
  --inconclusive \
  -j1 \
  --xml \
  --xml-version=2 \
  2> reports/cppcheck/context.xml
```

### Command Options

| Option | Description |
|---------|-------------|
| `--project=compile_commands.json` | Uses the compilation database generated by Bear. |
| `--enable=all` | Enables all available Cppcheck checks. |
| `--inconclusive` | Reports lower-confidence findings that may require manual verification. |
| `-j1` | Runs the analysis using a single thread to produce deterministic results. |
| `--xml` | Generates XML output. |
| `--xml-version=2` | Uses version 2 of the XML output format. |

### Result

The analysis completed successfully.

Generated report:

```text
reports/cppcheck/context.xml
```

---

## Running a Security-Focused Analysis

After evaluating the context-aware analysis, a second scan was performed using a reduced set of checks to minimize informational and style-related findings while keeping warnings that are more relevant for security analysis.

### Command

```bash
cppcheck \
  --project=compile_commands.json \
  --enable=warning,performance,portability \
  --inconclusive \
  -j1 \
  --xml \
  --xml-version=2 \
  2> reports/cppcheck/cppcheck-final.xml
```

### Result

The analysis completed successfully.

Generated report:

```text
reports/cppcheck/cppcheck-final.xml
```

# Comparison of Analysis Results

## Total Findings

| Analysis Configuration | XML Report | Total Findings |
|------------------------|------------|---------------:|
| Baseline analysis (no compilation context) | `cppcheck-result.xml` | **1687** |
| Context-aware analysis | `context.xml` | **1389** |
| Context-aware security-focused analysis | `cppcheck-final.xml` | **89** |

The compilation context reduced the number of reported findings from **1687** to **1389** (approximately **17.7% fewer findings**). Restricting the enabled checks to warning, performance, and portability categories further reduced the report to **89 findings**, producing a significantly cleaner output for manual review and later import into SonarQube.

## Rules Removed After Applying Compilation Context

The following rule categories were reported only in the baseline analysis and disappeared after using the compilation database:

- `bitwiseOnBoolean`
- `clarifyCondition`
- `constParameter`
- `constVariable`
- `ctunullpointer`
- `invalidscanf`
- `missingReturn`
- `redundantCondition`

This indicates that these findings were caused by incomplete build information and were eliminated after providing the actual compilation context.

---

## Rules Excluded from the Final Analysis

The final security-focused analysis intentionally excludes informational and style-oriented findings such as:

- `missingInclude`
- `missingIncludeSystem`
- `unusedFunction`
- `variableScope`
- `unknownMacro`
- `constParameterPointer`
- `constVariablePointer`
- `shadowArgument`
- `shadowFunction`
- `shadowVariable`
- `unreadVariable`

This configuration produces a concise report focused on findings that are more valuable during security review, including:

- `uninitvar`
- `nullPointer`
- `ignoredReturnValue`
- `shiftTooManyBitsSigned`
- `arithOperationsOnVoidPointer`
- `negativeIndex`
- `preprocessorErrorDirective`

---

## Conclusion

Using the compilation database generated by **Bear** allowed Cppcheck to analyze the BIRD source code using the same compiler options, include paths, and preprocessor definitions as the actual build process. This reduced configuration-related findings and improved the quality of the analysis. A second, security-focused configuration further reduced analysis noise by excluding informational and style-related findings, producing a report better suited for manual review and integration into SonarQube as external issues.
